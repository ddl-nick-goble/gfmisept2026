## Presenting

Open the URL in Chrome and press `F`.

| Key | Does |
|---|---|
| `→` `space` `PageDown` | Next fragment, then next slide |
| `←` `PageUp` | Back |
| `S` | Speaker notes |
| `T` | Elapsed clock against 30:00. `0` resets |
| `O` | Overview grid, click to jump |
| `F` | Fullscreen |

The URL tracks your position, so `.../gfmisept2026/#17` opens at slide 17 and a reload resumes where you were.

**Mirror your display, don't extend it, or the room reads your notes when you press `S`.**

**Keep the local copy open in a second tab.** Conference wifi is conference wifi, and a 400 KB page plus four videos is still a network dependency you don't need on stage. `hitl-deck.html` in the project folder is the same deck and needs nothing.

## The four videos

`index.html` looks for these **in this folder**, by exact filename:

```
demo-vibe-coding.mp4     slide 8    committed, 16.8 MB, 2:35
demo-control.mp4         slide 26   not yet
demo-validate.mp4        slide 27   not yet
demo-audit.mp4           slide 28   committed, 24.9 MB, 3:53
```

Any that are missing show a placeholder card naming the file, so the deck presents fine before they exist.

In the PDF handout, a slide whose video exists prints its poster frame; one still waiting on a file prints the placeholder card.

**While a demo plays, the caption band collapses and the video goes full bleed.** A 1080p screen recording letterboxed above the caption renders UI text at about half size, which the back of a conference room cannot read. Full bleed gets it to two thirds. The caption returns the moment you pause, and it is always present in the PDF.

To prepare them:

```bash
chmod +x prep-videos.sh
./prep-videos.sh ~/Movies/raw-control.mov control
```

That writes `demo-control.mp4` and `poster-control.jpg` with the settings that matter:

- **`-movflags +faststart`.** The index goes at the front of the file. Without it, Chrome downloads the entire video before showing frame one, which on stage looks like a broken slide.
- **H.264 high profile, yuv420p, AAC.** Plays everywhere including Safari.
- **CRF 24, capped at 1920 wide.** Screen recordings compress well; a three-minute demo lands around 15 to 30 MB.

### Size limits, in order of how much they will ruin your day

1. **Never use Git LFS for these.** GitHub Pages serves the LFS *pointer text* instead of the video. The `<video>` element fails, the slide silently falls back to the placeholder, and nothing tells you why. This is the one that catches people.
2. **100 MB hard limit per file**, warning at 50. Keep each demo under ~45 MB.
3. **1 GB soft limit** on a published Pages site. Four demos is not close.

### How the deck loads them

Measured, not assumed. On a range-capable server with a 6.7 MB demo in place:

- **Page load transfers 514 KB total**, which is the deck plus four poster frames. Zero video bytes.
- Each video's `src` is withheld until you are one slide away from it. The deck asks the server whether the file exists with a `HEAD` request, which transfers nothing, and uses that to decide between the video and the placeholder card.
- Arriving at slide 25 starts buffering slide 26's demo, so it's ready when you get there.

Chrome does not reliably honour `preload="metadata"` on a large file, so relying on that alone pulled all four videos on page load. This does not.

Over `file://` the deck detects it isn't hosted and skips all of that, because local bandwidth is free.

## Turning Pages on

1. Put these files at the repo root on `main`.
2. **Settings → Pages → Source: Deploy from a branch → `main` → `/ (root)` → Save.**
3. Wait a minute, then load https://ddl-nick-goble.github.io/gfmisept2026/

```bash
git add -A
git commit -m "GFMI deck"
git push
```

### Before you make this repo public

A public repo means the demo videos are downloadable by anyone with the URL, and they will be indexed. If any of them show unreleased product, internal tooling, real customer names or live data, that decision needs to happen before the first push, not after. Git history keeps what you push even if you delete the file in a later commit.

If the demos can't be public, the options are: private repo with private Pages (needs GitHub Enterprise Cloud, and viewers must be signed in to your org), or public deck with the videos on a host that expires links, referenced by absolute URL in place of the relative filenames.

## If a video doesn't play

| Symptom | Cause |
|---|---|
| Placeholder card with the filename | The file isn't there, or the name doesn't match exactly, including the hyphen |
| Placeholder card, but the file is committed | Git LFS. Check for a `.gitattributes` entry on `*.mp4` |
| Long black pause, then it plays | Not faststart. Re-run `prep-videos.sh` |
| Plays locally, not on Pages | Case sensitivity. Pages is case-sensitive, macOS isn't |
